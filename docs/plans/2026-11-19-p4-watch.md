# P4: Watch (`fleet/watch`)

Status: draft, 2026-11-19. Phase plan under the backend plan (`docs/plans/2026-11-19-backend.md`). Common rules are in
its "Phase schedule (waves)" section. P0 records: [S4](../decisions/p0-s4-connector-hub.md),
[S5](../decisions/p0-s5-memory-tool-choice.md).

## Goal

The Watch stage works on real data: the connector hub's core, Shopify read through it, routines with the morning
check, and Today, Activity, Library and the bell on the server.

**Success measure (the real slice):** the morning check reads the development store and fills Today.

## Scope

In:
- **Hub core** (first piece, also the base for P5): the gateway Worker (`app/hub/`), reached from the product Worker
  by a service binding; a `SignIn` Durable Object per connector account holding the token in its storage, never in
  isolate memory; AES-GCM encryption under a versioned key held as a Worker secret, with rotation; the runner's scope
  read only.
- **Shopify read:** a Dev Dashboard app per brand with the client credentials grant (24 h tokens the hub refreshes);
  level 1 protected customer data (no names, emails, phones or addresses); `read_returns` in the read scopes; tools
  named `resource_action`, loaded on demand through tool search; bounded results (a limit, paging and field selection
  on every read); `sku` as the only key on the inventory tool (S5).
- **Routines:** schedules in D1; the BrandAgent alarm wakes for the next due slot and starts one run per slot, keyed by
  the slot; a missed-run rule per routine; single-shot `query()` runs; the `inhouse` routine tools; the Routines page
  real.
- **The morning check:** a routine that reads the store and writes Today's "needs you" items with their sources.
- **Today, Activity, Library and the bell** on the server: Today's items, the activity log, files in R2 with rows in D1
  (by place and type, uploads by the team, permission-checked downloads, delete and restore), notifications and read
  state.
- Nightly connector tests against the seeded development store, a fixed fixture never reseeded per run.

Out: OAuth connectors, code mode and Slack (P5); any Shopify write (P6); approvals (P6).

## Inputs and gates

- P3 merged into `main`.
- **Prepared during wave 3 (orchestrator, with Wasim):** a P4 development store seeded once as the fixture (dev stores
  take 5 orders a minute, so seeding takes hours; refunds can't be backdated, so dated refunds are made on their day),
  using a seed app Wasim installs and removes afterwards; the brand-style Dev Dashboard app with read scopes. Its
  credentials reach Workers only through secret cards.
- Stage gating follows the server's stage (C2): the morning check runs at every stage; routines the team creates need
  Act, as the demo shows.

## Design notes

- **Hub layout.** `app/hub/` with its own config template `app/wrangler.hub.jsonc` (no account ids). Connectors live in
  `app/hub/connectors/<tool>/`. The product Worker never holds a tool token.
- **Morning check output** is a typed list (the shared schema's Today item: severity, area, title, sources, the
  numbers behind it as `{ minor, currency }` and instants as `{ iso, ms }`). The routine writes through an `inhouse`
  tool, not free text, so Today never parses prose.
- **Prompts** live in `app/server/prompt/` (orchestrator only). A prompt change runs the eval suite before it merges.
- **The mock** gets any contract change first; in this phase W4 owns `src/agent/mock.ts` and takes the others' mock
  changes.

## Browser scenarios (`e2e/ship/watch.spec.ts`, desktop and phone, fixture store, scripted model where the answer must be fixed)

- S1: Run the morning check from Routines; Today fills with the store's items and the right count.
- S2: Open an item; the problem panel shows the orders behind it from the store.
- S3: Ask which orders are late; the answer streams with a bounded table and its sources.
- S4: Activity shows the morning check's run with its time.
- S5: The bell shows the new notice; marking it read clears the dot after a reload.
- S6: Library shows a file the agent made; it downloads; deleting and restoring it works.
- S7: Routines shows the morning check's next run on the brand's time zone.

## Acceptance

1. A routine runs once per slot under repeated alarms (tested by firing the alarm twice); a missed slot follows its
   rule.
2. The morning check on the fixture store produces the expected items in the graded set; Today reads only typed items.
3. Every Shopify read returns at most its bound, pages beyond it, and never a level 2 field (a test asserts the field
   list).
4. The hub refreshes the 24 h token before expiry; a token never appears in the product Worker, the container or a
   log; key rotation re-encrypts and old tokens still decrypt until rotated.
5. The runner has no write path: a write operation sent through the runner's scope is refused at the hub.
6. Library downloads are permission-checked; a Member can't fetch another person's chat file.
7. The nightly connector tests pass against the fixture store without reseeding it.
8. API specs and the contract suite pass for the P4 methods.
9. QA PASS and the ship recording on S1 to S7.

## Must not

No tool token outside the hub's `SignIn` storage; no Shopify write; no level 2 customer field; no reseeding the
fixture per run; no unbounded read reaching the model; no real brand store in tests or previews; no retries in tests.

## Risks

- Seeding at 5 orders a minute and refunds on their day: start in wave 3, record the fixture's shape, never depend on
  "today" in assertions.
- Shopify API version changes: pin the API version and test it nightly.
- Morning check quality depends on prompts: the graded set gates prompt changes.
- The hub is new infrastructure that P5 builds on; H0 lands first and is reviewed at high.

## How it lands

- Branch `fleet/watch` from `main` after P3 merges.
- Review rows: H0 and W2 at Sonnet plus Opus high (tokens, concurrency); W1, W3 to W6 Sonnet plus Opus medium; prompt
  changes go with their eval results.
- Final PR with the full ship gate; the house deployment's release and smoke follow, with Wasim's OK.
