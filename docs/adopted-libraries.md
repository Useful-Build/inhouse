# Adopted libraries

The register of the base libraries the app is built on, one entry per library. An entry says where the library sits in
the code, why we use it, how it's pinned and where its changelog is. Read it before bumping one of these, and add an
entry when a new base library is adopted. Versions live in `app/package.json`, not here.

## In use

**Streamdown** (`streamdown` 2.8.1 and `remark-breaks` 4.0.0, exact pins). Layer: markdown rendering of an answer and of a skill's instructions, `src/screens/chat/markdown/`. Why: half-written markdown, GitHub markdown and a layered sanitizer, maintained by Vercel; chosen over react-markdown, markdown-to-jsx, Comark and Markstream on 2026-11-20 (plan file); built 2026-11-25 (`docs/history/UI_BASE_V2.md`). Streamdown and its parsers are about 170 KB gzip (measured with a one-off esbuild bundle of the package, not the product build), so `markdown/index.tsx` loads `markdown/renderer.tsx` as its own chunk when the browser is idle (the plain text shows until then) and `build-support/markdown-entry.test.ts` pins that nothing imports the renderer up front; Today's first load has a budget (`scripts/check-bundle.mjs`). Configured: `mode` always `streaming` (its `static` mode is a different tree, so switching to it when an answer finishes would remount the answer and redraw its diagrams), with `isAnimating` and `parseIncompleteMarkdown` only while the text is live, one block (`parseMarkdownIntoBlocksFn` returns the whole text, so the numbering, quote and table rules see it all); `skipHtml`; `controls={false}`, `lineNumbers={false}`, `linkSafety` off, `disableAutolinkProtocols ['mailto']`. Remark = the defaults (GFM, code meta) plus ours: raw HTML becomes text (`remarkHtmlAsText`), `remark-breaks` (a single newline is a break), and `remarkTableWidth` (a row wider than the header widens the table, GFM would drop the cells). Rehype = `lowercase schemes` (ours, first), the defaults minus `raw` (read from `defaultRehypePlugins`, so a new key shows up), `harden` set per call and ours last (`rehypeNumberBlocks`, which numbers code blocks, tables and diagrams apart and marks the last `pre`). `harden`: in chat `allowedLinkPrefixes` and `allowedImagePrefixes` are `https://<host>/` (and `http://<host>/`, for the `www.` rewrite) for each host the caller lists (the answer's WebFetch hosts, none while it streams), `defaultOrigin` a reserved `.invalid` origin, `allowedProtocols []`, `allowDataImages false`, link and image block policy `text-only` (the `span` it leaves is unwrapped); on a page (a skill's text, written by the team) any https address passes. The components check every address again with the same rules (`policy.ts`): exact host, https only, no port, no credentials, no `mailto:`, a bare or `<url>` address only when listed, images only when listed (a page loads none), in-app `#/` routes always. Overrides: `a`, `img`, h1-h6 shifted one level (`#` is h2, no h1; a page's `#` and `##` are both h2), `p`, `strong`, `blockquote`, lists, `code`, `pre` (the base Code Block through `src/ui/code-snippet.tsx`, plain text, region name and Copy button from `dataMdN`), `table` family (region, name, `data-md-table`), `input` (task boxes) and every other element Streamdown styles, so none of its Tailwind classes reach the page. The `>` quote rule is a pre-step (`keepBareGreaterThan`: only `> ` or a bare `>` starts a quote). Mermaid diagrams are our own `pre` branch, not Streamdown's plugin (see the Mermaid entry). Not used: `@streamdown/code` and shiki, math, `@streamdown/mermaid`, cjk, `animated` (the answer's pacing is `reveal.ts`), built-in controls, the link safety modal. Upstream issue https://github.com/vercel/streamdown/issues/767 (2.8.0 rewrote every `#x` href to `#user-content-x`, breaking `#/` hash routes) is closed and 2.8.1 passes `#/tools/x` through, so there is no workaround; `markdown-links.test.ts` pins it. Changelog: https://github.com/vercel/streamdown/releases. Guarded by: `streamed.property.test.ts`, `markdown.differential.test.ts`, `build-support/markdown-entry.test.ts`, `markdown-links*.test.ts`, `conversation.spec.ts`.

**Mermaid** (`mermaid` 12.3.0, exact pin; `@streamdown/mermaid` is deliberately not installed). Layer: a ` ```mermaid ` fence in a chat answer or a skill's instructions is drawn as a diagram, `src/screens/chat/markdown/diagram*.ts(x)`; added 2026-11-25 (`docs/history/UI_BASE_V2.md`, PR A2). Why: it is the standard text-to-diagram format and the agent already writes it. Why not `@streamdown/mermaid` (1.0.4, wraps `mermaid` ^11): it imports `mermaid` statically, so loading the plugin loads all of Mermaid, and its diagram block brings Streamdown's own Tailwind classes, which this app's build never generates. Our `pre` override already replaces Streamdown's code block, so the plugin would sit unused. Loading: `diagram-engine.ts` is the only file that names `mermaid`, with `import('mermaid')` the first time a diagram is drawn. A text with no mermaid fence never loads it: it is not in the entry chunk and not in the renderer chunk, and Vite splits it and its per-diagram parsers into their own chunks (it is large: about 3.3 MB of unminified chunks in the package, so expect a few hundred KB gzip for the core and flowchart parts, not measured here). `build-support/markdown-entry.test.ts` and `diagram-engine.test.ts` pin both. Security (an answer is untrusted text): `securityLevel: 'strict'` (no click handlers, Mermaid sanitizes its own output), `htmlLabels: false`, `suppressErrorRendering: true`, `startOnLoad: false`, and `secure` = Mermaid's defaults plus `htmlLabels`, `flowchart`, `theme`, `themeCSS`, `themeVariables`, `fontFamily`, `altFontFamily`, `look`, `layout`, `arrowMarkerAbsolute` and `darkMode`, so a diagram's own `%%{init}%%` or frontmatter can't set them (without it, a diagram could turn HTML labels back on and add theme CSS, and it stayed in force for the next diagram); `diagram-engine.ts` runs each `initialize` and `render` one at a time, since the config is global. `diagram-svg.ts` then unwraps `a` (a linked node stays drawn), removes `image`, `feImage`, `script`, `iframe`, `object`, `embed` and the animation elements, `on*` attributes and any `href` that is not a `#fragment`, and drops any CSS part or attribute holding a non-fragment `url()` (same-origin ones too: the CSP lets a same-origin or `data:` image load with the session's cookies), `image-set()`, `image()`, `src()`, `@import` or a backslash escape, in `<style>` text, `style` attributes and presentation attributes alike; a figure that still has a `foreignObject` (some diagram types draw HTML whatever the config says) fails to its source. Each draw takes a new id (`mermaid.render(id)` removes the element with that id, which would take the figure on screen away during a theme redraw), and drawn figures are kept by number, theme and source, so a remount shows them at once. Not used: the `sandbox` level (it draws in an iframe, which the CSP's `default-src 'self'` would not let load a data: page). The CSP in `app/public/_headers` is not loosened: Mermaid's chunks are same-origin scripts (`script-src 'self'`), its figure carries an inline `<style>` (`style-src 'unsafe-inline'`), and its dist holds no `eval` or `new Function`. Look: `theme: 'base'` with `themeVariables` read from the role tokens (`--card`, `--fill`, `--border-strong`, `--foreground`, `--foreground-3`, `--muted`, `--font-sans`) at each draw, converted to hex when a token is not hex or rgb; a theme change (the `dark` class on `<html>`) redraws. While a fence is open and the text is live, and until the chunk has loaded, a quiet "Drawing diagram…" line shows; a diagram that fails to parse after the fence closes shows "Couldn't draw this diagram." over its source as a code block, and `console.error` logs the error. The figure is `role="img"` with an `aria-label` ("Diagram N", plus its own title), inside a keyboard-scrollable region, with Show source and Copy. In Dependabot's `registered` group: read each release's security notes, and re-check the default `secure` keys, before a bump. Changelog: https://github.com/mermaid-js/mermaid/releases. Guarded by: `diagram.test.ts`, `diagram.property.test.ts`, `diagram-engine.test.ts`, `diagram-svg.test.ts`, `diagram-config.test.ts`, `diagram-remount.test.ts`, `build-support/markdown-entry.test.ts`, `conversation.spec.ts`. The DOM tests run under `jsdom` (dev dependency, exact pin, per-file `@vitest-environment`; happy-dom was tried and drops an svg's `<style>` text when parsing).

**MCP TypeScript SDK, client** (`@modelcontextprotocol/client` 2.4.0, exact pin, in `app/hub/package.json`; brings `@modelcontextprotocol/core` 2.4.0, `eventsource-parser`, `pkce-challenge`, `jose`, `eventsource`, `cross-spawn` and `zod` ^4.2). Layer: the hub's MCP client, `app/hub/connectors/mcp/sdk.ts` only, over our fetch adapter (`mcpFetch` in `app/hub/oauth/http.ts`); added 2026-11-28 (Stage 1 M4-C1, plan N36). Nothing calls it yet: the hand-written `connectors/mcp/client.ts` serves Slack until M4-C2 moves it. Why: the official implementation of MCP 2026-07-28 (`server/discover`, per-request `_meta`, `Mcp-Param-*` mirroring, `input_required`) and 2025-11-25 in one client, with era negotiation, instead of a second hand-written protocol. How we use it, protocol only: the transport never gets an auth provider, so the SDK's `auth()` never runs (it drops a login on `invalid_client`, restarts sign-in on an outage and logs a token endpoint's raw answer with `console.warn`); the hub keeps its own renewal. Set against its defaults: `versionNegotiation: { mode: 'auto' }` (default `'legacy'`), `onInsufficientScope: 'throw'` (default `'reauthorize'`), `inputRequired: { autoFulfill: false }` with `allowInputRequired` per call, SSE reconnection off, every `tools/call` given the confirmed definition as `toolDefinition` (else it lists and retries on `HeaderMismatch` by itself), lists through `client.request('tools/list')` page by page (`listTools()` serves its cache and writes `console.debug`/`console.warn` lines). Our fetch sends only to the exact endpoint, never follows a redirect, answers a GET or DELETE itself, caps a write at one `tools/call` POST, refuses `initialize` after a modern error, and stops reading an event stream at the matching answer. Bundle: on workerd its `_shims` export resolves to `shimsWorkerd`, which loads its `@cfworker/json-schema` validator (inlined in the package; output-schema validation stays off because the definition we pass carries no `outputSchema`); `scripts/check-hub-build.mjs` part 3 fails either hub bundle that carries its stdio entry, `cross-spawn`, its Node shim, the AJV validator, a `validators/*` entry, `ajv` or the official server. **Server** (`@modelcontextprotocol/server` 2.4.0, exact pin, hub dev dependency, never bundled): the cross-check and the differential test against M4-F's fakes (`connectors/mcp/sdk.official.test.ts`). Before a bump: re-read the client's `ClientOptions` and `StreamableHTTPClientTransportOptions` defaults, `probeClassifier.ts`, `callTool`'s recovery and every `console.*` call in the package (the source maps carry the source). Changelog: https://github.com/modelcontextprotocol/typescript-sdk/releases. Guarded by: `connectors/mcp/sdk.test.ts` (wire counts, plants, no console), `sdk.official.test.ts`, `sdk.workers.test.ts` (workerd), `scripts/check-hub-build.test.mjs`.

## Learned from (not installed)

## Per-update procedure

1. Dependabot: the `registered` group in `.github/dependabot.yml` matches `streamdown`, `@streamdown/*` and
   `remark-breaks`. A dependency goes to the first group it matches (docs.github.com Dependabot options reference, read
   2026-11-20), so these bumps arrive alone. The npm entry has `cooldown: default-days: 14`, which applies to version
   updates only. Security updates still come at once.
2. On each such PR, read every release note between the old and new versions and write in the PR: breaking changes and
   deprecations that touch our settings or overrides, security fixes, and new features worth adopting. Check whether
   `defaultRehypePlugins` gained or lost a key, since we filter it.
3. Run the full CI and E2E. Merge only the bump. A feature gets its own PR.
4. If any kept rule weakens (the property tests or the differential fail, or a default moves), stop and report. Don't
   patch around it inside the bump.

## Periodic re-scan

At the two-month setup review (first 2027-01-15), per layer (markdown, chat UI kit, UI base, state, validation),
search current sources, not this register's list. Report keep, upgrade or switch, with dated evidence and measured size.
