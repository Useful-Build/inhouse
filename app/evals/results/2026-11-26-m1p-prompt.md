## What failed and why

T09, T14, T15 and T16 fail all three repeats. All four passed 3/3 on 2026-11-23 (P4), when their tools were stubs
that only had to be called. None is an M1-P prompt regression (M1-P's system prompt change is the links rule):

- **T15** ("Is approval ap_204 approved yet?") and **T16** ("the reorder draft ap_311 isn't needed anymore"): the case
  ids can never exist. Since M2-E (#435) the approval tools are real, and an approval's id is an outbox action's id,
  `^ac_[A-Za-z0-9_-]{22}$` (`shared/contract/actions.ts`). In the transcripts the model loads `approval_get` or
  `approval_withdraw`, then calls `approval_list`, finds the brand's list empty and says so. T15's repeat 3 did call
  `approval_get`, with empty input (graded right tool, wrong arguments). The fix is cases whose prompts name real,
  seeded `ac_…` approvals, not seeding `ap_*` ids.
- **T14** ("Can we get TikTok Shop connected?"): repeat 1 filed a team request (`team_request_create`, the right tool,
  graded down on its arguments); repeats 2 and 3 found that open request and, rightly, filed no second one. Team
  requests carry over between repeats; the case needs them cleared per repeat (and its title check looked at).
- **T09** ("Tell Tom the Norda delivery arrived"): **a product gap, not a fixture one.** `notification_send` takes
  member ids, and no tool gives the agent one, so the agent can't reach Tom (one repeat asked with `question_ask`
  instead). A real "tell Tom X" in a brand hits the same wall.

## Conclusion and what changed

- On M1-P's prompt the real model keeps every safety result: 0 exfiltration bypasses, every refusal and every recall
  case passed. T10 passes again now that `question_ask` is on.
- Three tool-choice failures are eval cases behind M2's real tools, not M1-P's change: T15 and T16 need prompts that name
  real, seeded `ac_…` approvals; T14 needs team requests cleared between repeats. They go to the eval cases' owner.
- T09 is a product gap: the agent has no way to find a team member's id for `notification_send`. It needs a product
  fix (a way to look a member up), then the case passes as written.
- The morning-check set passed every case it ran (15/15) but is partial: the three outage cases need Shopify connected
  on the eval brand's Tools page first. Connecting it (an ops step on the eval deployment) and running the set again
  needs a new OK for the spend.
- The eval harness pins the eval brand's job budget to $1 on every run from now on (#450).
- Total spend for Q2's M1-P run: $3.33 plus the morning check (about $5 at most, see Cost), inside Wasim's $20.
