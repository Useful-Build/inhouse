# Inhouse design layer

The app runs on ui-base v1.1.0, the shared shadcn/ui (Radix) and Tailwind v4 base. ui-base is the base registry, so it isn't linked here. `DESIGN_SYSTEM.md` is the base's guide: it's base-owned, so every `update` rewrites it. Read it first for the role tokens, the scales and the base components. This file is Inhouse's own layer on top, and it's app-owned: an update never touches it.

## Layers

| Layer | Where | Rule |
|---|---|---|
| Base tokens | `src/ui-base.css` | Base-owned: never edit it. Every role token for light and dark, the Tailwind theme, base styles, `ellipsis` and `mono-label`. |
| App CSS | `src/index.css` | App-owned. Imports `ui-base.css`, then holds the self-hosted `@font-face` rules, the override block (`--font-sans` and `--font-mono` in `:root`, since Inhouse self-hosts Geist instead of the `@fontsource` packages, and the dark values in `.dark`, see [Dark](#dark)), the `--app-*` role tokens with their `@theme inline` mappings, and the app's helpers (`ms`, `on-page`, `page`, `picked-muted`, the agent mark). |
| Components | `src/components/ui/*.tsx` | Base-owned, except `icon.tsx`. Never edit them: an app-only look goes in a `src/ui` wrapper, a look every app needs goes to ui-base in a release. |
| Icon seam | `src/components/ui/icon.tsx` | App-owned. Material Symbols Rounded, self-hosted in `public/fonts`. `name` is any Material name; the base's names in `icon-names.ts` are mapped in `BASE_ICONS`, so a release that adds one fails the type check here. |
| Merge names | `src/lib/merge-config.ts` | App-owned. Every class name an `--app-*` token adds, so `cn()` keeps it next to a base class. |
| App primitives | `src/ui/` | Inhouse-only pieces built on the components: `Button` and `IconButton` (with the app-only variants), `Icon`, `AgentMark`, `LogoTile`, `Window`, `Confirm`, `Select`, `SearchBox`, `NavItem`, `MenuItem`, `SelectionBar`, the page parts... |
| Screens | `src/screens/`, `src/overlays/`, `src/shell/` | Compose components with Tailwind classes. No colors, no one-off sizes. |

## Where Inhouse differs from the base guide

- **Fonts:** Geist, Geist Mono and Material Symbols are self-hosted in `public/fonts` (`@font-face` in `src/index.css`), not imported from `@fontsource-variable`. The override block points `--font-sans` and `--font-mono` at them.
- **Disabled look:** only a disabled primary `Button` dims. The `src/ui` `Button` (every other variant), `IconButton`, `Select` and `Switch` add `disabled:opacity-100`, which cancels the base's `disabled:opacity-50`, and `MenuItem` does the same for `data-[disabled]`. Nothing else is dimmed with opacity either: a handled or approved card's text is `text-done`.
- **Brand color system (Option B: Obsidian and Slate Ink):** `src/index.css` overrides `ui-base.css`'s color tokens to keep ~95% of chrome in pure gallery monochrome (`#fafafa` / `#111113` canvas, `#ffffff` / `#19191c` cards, `#151517` / `#ededef` ink) and replaces the base's violet-indigo `--brand` with quiet deep Sapphire (`#1f44a8` light, `#7b9ef0` dark; draft sheet `#f5f7fb` / `#181b24`), harmonized amber warning, terracotta destructive and the app-owned `--app-success` family (`#1e6b45` / `#55b886`).
- **Page background (Turrell Skyspace):** `SkyspaceBackground` mounts on the full app shell behind both the floating sidebar and main (zero vertical seam), using `--app-cove-*` tokens. Full hero intensity on Today and blank New chat, softly quieted (`opacity-35`) behind messages in an active chat, and plain `--background` on other pages.
- **Status pills and badges:** Status `Badge` pills and Today clear-state tool pills carry crisp typography without decorative status dots.
- **Theme:** `src/lib/theme.ts` holds light, dark or system, saved per browser. An inline script in `index.html` applies it before first paint, so there's no flash. There's no `ThemeProvider`.
- **Regression suite:** the app's own, not the base's: `npm run test:visual` compares every screen in light and dark with committed baselines and `npm run test:a11y` runs axe on them (see `README.md`). Update the baselines on purpose when a change is meant to show.
- **Extra scale steps:** `rounded-2xs` 2px and `rounded-t-bar` 5px (a chart bar's top). Spacing: prefer whole and half steps; any quarter step is a pixel (`w-82.5` = 330px, `gap-0.75` = 3px). Flex parts: `grow basis-55` for `flex: 1 1 220px`. Percent widths are fractions (`w-31/50` = 62%).
- **Motion:** `animate-mark-1` to `3` move the agent mark's dots (`agent-dot-1` to `3` place them, `goo` blends them). The important modifier `!` is allowed in one place: switching off shadcn's `animate-in` and `animate-out` on a window, panel or menu (`NO_MOTION` and `NO_CLOSE_MOTION` in `src/ui/motion.ts`). A plain `animate-none` loses to them, so use the constants and never write the class by hand or use `!` anywhere else.

## Dark

Dark is re-decided, not inverted. Every `:root` color override in `src/index.css` is re-stated in `.dark` so dark mode never inherits a light value, and the app tokens carry their own dark obsidian values.

Surfaces climb with height in cool obsidian steps: page `#111113`, card `#19191c`, window and side panel `#1f1f24`, menu and pop-up `#242429`. Rows have three states, each one value everywhere: **hover** (`bg-accent`, also a menu's keyboard cursor), **open** (a trigger whose menu is open holds its own hover look: `data-[state=open]:` or `aria-expanded:` with the same class as its hover) and **selected** (`bg-fill-hover`: the nav row, the open or picked chat, a Library place; a segmented control's pick is `bg-fill-picked`, the same value in dark). Muted text keeps 4.5:1 on hover; on a selected row it steps up to `text-foreground-3` (`NavItem` does it for `meta` and `detail`, `StageTag strong` for its tag, and `Segmented` for any muted text in its picked segment).

## Checks

`npm run lint` runs `lint:tokens`, which runs two scripts:

- `scripts/check-tokens.mjs`, base-owned: colors outside `src/ui-base.css` and `src/index.css`, and any `--name` in the override block that `ui-base.css` doesn't define (an app token starts with `--app-`). See `DESIGN_SYSTEM.md`.
- `scripts/check-app-rules.mjs`, app-owned: Inhouse's three extra rules (arbitrary values, literal inline styles, no fixed waits in e2e).

| Rule | Fails | Passes |
|---|---|---|
| Arbitrary values (not in `src/components/ui/`, which stays close to shadcn) | `w-[330px]`, `bg-foreground/[4.5%]`, `[overflow-wrap:anywhere]`, `[--app-pad-x:24px]` | variants (`data-[state=open]:`, `[&_svg]:`, `has-[...]:`), a token by name (`px-(--app-pad-x)`) |
| Inline styles in `.tsx` | a `style` value that is a number, a quoted string or a `var(--...)`, or picks one in a ternary (nested too) or falls back to one with `??`, `\|\|` or `&&` | a value computed from data or a prop (a bar's height, a position, a primitive's `size`) |
| No fixed waits in `e2e/` | `waitForTimeout(`, any `setTimeout` or `setInterval` (a `new Promise` holding one, an alias, `promisify`), the `timers` module in any form (`timers/promises`, `require('timers')`, `import('node:timers')`), `scheduler.wait`, `Atomics.wait` | `test.setTimeout`, `test.slow`, `page.clock.*`, condition waits (`expect`, `expect.poll`) |

Each failure prints as `file:line` and the offending text. The fixed-waits rule has no allow list. Exceptions for the other two, only for content art (a picture rather than UI):

- `scripts/check-tokens.allow.json` (colors, the base format: paths from the app root, no reasons in the file). Today: `src/screens/library/Previews.tsx` (drawings of file pages, a spreadsheet and a deck, with their own colors) and `src/ui/photo.ts` (colors painted into canvas photos).
- `scripts/check-app-rules.allow.json` (`files` with paths from `src/`, and exact `classes`). Today: `screens/library/Previews.tsx` (container-relative sizes in the file drawings), and no class entries. Add an entry only when the value truly can't be a scale step or a token, and give it a one-line `reason`. The check fails on an entry with no reason, a file that's gone or breaks neither rule, and a class nothing uses.

## App role tokens

A value the base scales can't express becomes an `--app-*` token, named by role, not by value. Register it in three places:

1. `src/index.css`: the value in the app `:root` block (and in `.dark` too if it differs by theme).
2. `src/index.css`: its mapping in the app's `@theme inline` block, so it's a class (`--container-sidebar: var(--app-sidebar);`). A font size goes in the last `@theme inline` block, after the base's `--text-*: initial`.
3. `src/lib/merge-config.ts`: the class name under its group (`container`, `spacing`, `leading`, `tracking`, `shadow`, `text`, `radius`, `animate`, `color`), or a `classGroups` entry when it isn't a theme scale (`bg-dot-grid`, `border-hairline`, `grid-cols-cards`, the `z` layers). Without it `cn()` drops one of two classes that don't conflict.

## Components

Use the component before building a look by hand. On screens, use the `src/ui` parts, not `components/ui` directly.

- `Button` (`src/ui`): variants `primary`, `secondary`, `outline`, `soft`, `ghost`, `link` (the base's), plus the app-only `destructive` (the app's red, `bg-destructive-solid`, so its text reads in dark), `surface` (a borderless card-coloured button for a tinted strip, like a banner), `inverse` (the dark toast and a selection bar; disabled, only its text fades), `quiet` (a back link) and `requested` (the quiet, already-asked state of a request button). The app-only looks render the base `Button` with no variant (`variant={null}`) and their classes in `APP_BTN`; a new app-only look goes there, never into `components/ui/button.tsx`. Pick a size: `sm` 28px (a small action in a row, like Undo), `default` 32px (actions on a card or a list row), `lg` 38px (a page's or window's main actions, next to fields), `xs` 22px pill (Pause in the status pill), `icon-sm` 28px square. Never set a height, radius or padding on the call. `outline` shows a pressed look when `aria-pressed` is true (Library's Select). Use `asChild` to render a link as a button.
- `IconButton` (`src/ui`, icon-only, with a tooltip): `size` is the glyph's size in px and `box` the button's own size step (`icon` 32px, `icon-sm` 28px, `icon-lg` 36px). Its `variant` is `ghost`, the app-only `chrome` for the app's frame (the top bar and the sidebar: a faint fill on hover and while its pop-up is open), `action` for the row of actions under a message (always at `box="icon-sm"`, 28px; `filled` for a picked rating; on a phone it adds `TAP_Y`, a 44px-tall tap area as wide as the button, so neighbours' areas don't overlap), or `inverse` on the dark toast (a light glyph, the inverse `Button`'s faint fill on hover: the toast's close). Never set a size on the call: pick `box`. Give it `shortcut` (from `SHORTCUTS` in `src/shell/nav.ts`) and the tooltip shows the keys after the label and the button gets `aria-keyshortcuts`. The floating round button (Jump to latest) is the base `Button` at `icon-round`. `tipSide` moves the tooltip (`right` in the collapsed sidebar).
- **Sidebar collapse button** (`src/shell/Sidebar.tsx`, desktop only): a `chrome` `IconButton` at 32px with an 18px glyph, named "Sidebar" with `aria-expanded` and `aria-controls="sidebar"`, its tooltip "Collapse sidebar" or "Expand sidebar" with ⌘\\ (`SHORTCUTS.sidebar`). Expanded, it sits at the end of the bottom row beside the account row (which drops its chevron on desktop), in line with New chat; on the rail it sits centred above the avatar, tooltip on the right, so the avatar keeps the bottom corner. A click on it keeps focus on the button in the new tree. The phone drawer has none (the top bar's menu button opens it, and the top bar has no sidebar button on desktop).
- Page parts (`src/ui/page.tsx`, exported from `src/ui`):
  - `Page` (`width`: `default`, `wide`, `detail`): the page's centered column at a width step (`detail` is a skill's page).
  - `PageHeader` (`title`, `description`, `actions`, `leading` before the title, `tag` beside it, `truncate` for a title the user named, cut with an ellipsis and shown in full in a tooltip): the h1 at `text-3xl` on every page, a tool's page too (its logo is `leading`, its status `tag`), a line under it only when it adds information (never one that restates the title), actions on the right that wrap under it when narrow. `leading` stays beside the title on a phone; `tag` sits beside the title, centred on its capitals, and under it (8px gaps) below `sm`.
  - `SectionHeader` (`title`, `count`, `icon`, `actions`, `onDots`, `id` so a `<section>` can be labelled by it): a section's h2, with a count always as "Title · 6". It sits on the page's content edge: never give it a left margin at the call. `onDots` adds the page-coloured patch for text straight on the dotted page (Today).
  - `CardGrid` (`size`: `sm`, `default`, `lg`; `variant`: `cards` for bordered cards, `rows` for borderless list rows in columns). `rows` bleeds out by a row's 12px padding (`p-3` on the row), so the rows' icons and buttons sit on the content edge with the section headings.
  - `DetailList` (`items` as `[key, value]`, `variant`: `ruled` with a divider under each row, `compact`, `relaxed` that puts the value under the key when narrow; `strong` for medium-weight values). A `dl`.
  - `EmptyState` (`variant`: `card` where a list would be, `inline` for a search with no results). Announced as a status.
- Locked items (a later stage, rows and nav items): `text-foreground-3` on the name, `text-muted-foreground` on the description and meta, a muted tile (`IconTile tone="locked"`) or `grayscale` on a logo or avatar, plus `StageTag` (which carries a hidden "Locked, included in a later stage" for screen readers, and says so in a tooltip on hover; `strong` on a selected row). Never dim them with opacity, which drops text below AA.
- `Switch` (`src/ui`): `small` in menus. Without `onChange` it's disabled and keeps its look. `reason` is one that can't change and says why (Smart, the default model): it stays focusable, `aria-disabled`, described by a `hidden` copy of the reason while the tooltip is closed (the open tooltip describes it, so it's heard once), and the reason shows in a tooltip on hover, keyboard focus and a click or tap (so a phone reaches it); a tap anywhere outside the switch, another switch included, closes it. Never a native `title`: use `Tooltip` for any hint.
- `NavItem` (`src/ui/chrome.tsx`): a nav row in the sidebar, the Settings menu and the Library's places, with one selected look (`bg-fill-hover`, a step above the `bg-accent` hover; the open chat's row matches). `meta` is a quiet number (a place's file count), `detail` a line under the label (a settings search's matches) with `size="fit"` (`tap` on a phone); `size="chip"` is a pill in a row (the Library's places below 1024px); both, and a `tag`, step up to `text-foreground-3` on the selected row. The account row is selected only on Settings; while its menu is open it holds its hover look. A Library place passes `aria-pressed` and `aria-current={undefined}`, since it filters rather than navigates. `rail` is the collapsed sidebar's 40px square: the label moves to a tooltip (`side="right"`) that a click closes until the pointer leaves, the count becomes a dot, and the name, count and stage tag stay for screen readers.
- **The More button**: where a card or window has one main action, every other action sits behind one outlined `Button` (`size="lg"`, beside the main one) labelled "More" with an `expand_more` chevron that opens a `DropdownMenu` of `MenuItem`s: the review window's footer (it opens upward, `side="top"`) and an Approvals card. Don't send is its first item, with a separator under it in the window. A smaller row or header (a Today card, a routine, a skill's page) keeps the icon-only "···" (`more_horiz`) `IconButton`; on a Today card it's `ghost`, with no fill until hover.
- `MenuItem` (`src/ui/chrome.tsx`): every row of a "···" menu, 38px with base text. `variant="destructive"` for Delete, `locked` for an item a later stage includes: picking it does nothing (the menu stays open, `onSelect` doesn't run). A `disabled` item takes the locked text (`text-foreground-3`), never the base's dim. Never set a height on a `DropdownMenuItem` by hand.
- `SelectionBar` (`src/ui/chrome.tsx`): Select mode's floating bar (Library, All chats): `status` then `inverse` buttons, a picked Delete `destructive`. `over` is the content it acts on (the chat list, the Library's files column): the bar centres on it, not on the window, as far as it can while keeping 12px from each window edge (it measures its own width); on a narrow phone the status truncates. While it shows, the page gives its last row room to scroll clear of it (`pb-24`). It carries `data-bottom-dock`, as does the chat's composer dock, and the toast stack sits above both.
- **The toast stack** (`src/shell/Toasts.tsx`): newest at the bottom, centred, at most four. It portals to `body` at `z-toast`, so a toast shows over a window's or sheet's scrim and its Undo takes clicks while one is open: every modal passes `keepForToast` (`src/ui/dialogs.ts`) to `onPointerDownOutside` and `onInteractOutside`, so a click on a toast isn't a click outside. The live region (`role="status"`, `aria-live`) is always mounted straight under `body`, so a Radix modal, which hides everything else from screen readers when it opens, leaves it announced. With nothing docked it sits at `bottom-toast` (above the safe area); otherwise it measures every `[data-bottom-dock]` element (the chat's composer dock, a `SelectionBar`) and sits `--app-toast-dock-gap` (12px, read by the component) above the tallest. Each toast is `bg-primary` with an `inverse` Undo `Button` and an `inverse` `IconButton` close named "Dismiss" and described by the toast's text (`aria-describedby`), both tap-size on a phone (`TAP`). Keyboard: **F6** moves focus to the newest toast's first button and remembers where focus was; Escape or F6 again returns it there (to `main` if that element is gone) without closing anything. There is no trap: Tab moves on and a click elsewhere just leaves. **While a modal window, sheet or confirm is open, F6 does nothing**: the modal keeps focus (an approval has its own Undo in the panel; a toast's Undo still takes a click). After Undo or Dismiss from the keyboard (a click with `detail` 0), focus goes to the next toast, or back once none is left; a mouse click moves no focus. If the focused toast leaves on its own, focus goes to the newest toast, or back. The toasts always render in the same parent, so moving focus never remounts one (its countdown and announcement stay as they were). Approvals going out share one toast (key `held`): each new one joins it ("Approved 3 drafts. They go out in 10 seconds."), its count follows as they go out, and its one Undo takes back every one that hasn't. Over four toasts, the oldest without Undo leaves; a notice never pushes out one with Undo (it shows as a fifth); a new Undo toast over four Undo toasts pushes out the oldest that holds nothing; and the held toast leaves only when its approvals went out, on its Undo or on its close. So the stack never passes five.
- `SuggestionChip` (`src/ui/chat.tsx`): a suggested question as a round chip that asks it: the empty chat's suggestions and the off-script answer's.
- **The chat's measures** (`index.css`, registered in `@theme inline` and `merge-config.ts`): the column is `max-w-chat-column` (880px), an answer's text `max-w-answer-measure` (`--app-answer-measure`, about 620px) and your bubble, tables, insets and the draft card `prose-measure` (about 520px), so an answer reads wider than what you wrote.
- **Steps and sources** (`src/screens/chat/Steps.tsx`): a finished answer has a steps line above its card, one quiet muted line ("Checked Shopify and ShipBob · 3 steps"; the count never truncates, the tool names do) that opens the step list in place with a Details link to the trace window. The card ends with one `bg-fill` pill (up to 3 overlapping round logos, "N sources", chevron) that opens a plain list; no numbered chips. Both are `aria-expanded` toggles, and opening one keeps the reader's place (the view doesn't follow it down). A draft to approve is its own `bg-draft-sheet` card after the answer's card.
- `Window` (`src/ui`): a centered window. `size` `sm` (a question, a notice), `md` (Help; the team window takes it at `w-today-column`, 720px), `lg` (the file viewer), `wide` (the review window: 960px, set lower at 14vh and at most 80vh tall), `xl` (the trace); `layer` `window`, `trace` or `confirm`. It opens with focus on the window itself, so Close shows no ring or tooltip until someone tabs to it; sheets and the phone drawer do the same. `initialFocus` only where a field or a safe answer should take focus (Confirm's Cancel). Every window is `bg-window-surface` with `data-surface="window"` (a side panel sets both too): never give one `bg-card`.
- `Confirm` (`src/ui/fields.tsx`): the one question before a change that takes something away (Delete, Replace, removing a role). Never build another.
- `SearchBox` (`src/ui/fields.tsx`): one look and size everywhere (38px, a card-coloured field with an input's border). It's a field, never a fill, so it can't read as the selected row under it in the Settings and Library menus. `className` only places it in its row.
- `IconTile` (`src/ui/chrome.tsx`): `size` `md` 34, `lg` 40, `xl` 46px; `tone` `fill`, `hover`, `outline`, or the solid `ink`, `brand` and `locked` (Skills).
- Help's guides are the Radix `Accordion` (`src/components/ui/accordion.tsx`, the stock shadcn file with only its import fixed and lucide swapped for `Icon`, the app's own until ui-base adopts it). Inhouse's look is `Guide` (`src/ui/chrome.tsx`): one guide with its icon tile and title. Never restyle the stock file.
- The command palette (`src/overlays/CommandPalette.tsx`) is `Command` inside a `Dialog`, with no motion (`NO_MOTION`).
- `Badge` (the base's): `secondary` on a card, `muted` straight on the page, `warning` and `status` for status (`brand` and `destructive` exist in the base but the app doesn't use them). `Separator` draws the in-card divider color; on the page give it `bg-border`.
- Every logo sits on a logo tile: `LogoTile` from `src/ui`, by `size`: `xs` 18px (in a line of text), `sm` 22px (a menu row, a card's label line; `round` for the composer's stack, whose glyph is 2px smaller so it clears the circle), `md` 32px (a setup row), `lg` 46px (a tool row, the default), `xl` 64px (a tool's page). `LogoCount` is the "+N" after a round stack, on a tile of the same `size`. The logo itself isn't exported, since some marks vanish on a dark card.
- `ChoiceChips` (`src/ui`): wrapping pill choices with one pick, for a short set that may wrap onto two lines. Use `Segmented` when the options fit one track.
- One icon system: `Icon` (Material Symbols Rounded) from `src/ui`, which re-exports `src/components/ui/icon.tsx`.
